# 项目架构约定

本项目采用分层架构，不强制套用传统 MVC：

- `interface`：桌面界面入口和前端桥接，职责接近 Controller。
- `features`：发布、同步等用例，以及具备业务含义的数据模型。
- `platforms`：番茄平台自动化实现。
- `infrastructure`：配置、文件、桌面对话框等技术实现。
- `runtime`：应用路径、运行设置、任务和日志等跨功能运行能力。
- `bootstrap`：组装用例和依赖。

## 什么时候使用模型

以下数据应使用 `dataclass`、`Enum` 或 Pydantic 模型：

- 跨越模块边界的数据；
- 需要类型校验、默认值或序列化的数据；
- 具有业务含义的选项、状态和结果；
- 生命周期内需要保持一致性的状态。

临时 DOM 信息、一次性局部计算结果和简单转换值不需要单独建立模型。

## 什么时候使用类

浏览器会话、提交状态流、配置仓库和任务协调器拥有状态或资源生命周期，使用类管理。

文本标准化、章节解析、差异计算、文件名生成等输入输出明确且无状态的逻辑保持为纯函数。

## 公开和私有接口

- `_name` 只允许当前模块内部使用。
- 生产代码不得跨模块导入以下划线开头的名称。
- 一旦其他模块需要调用，应将其提升为公开接口或移动到合适的共享模块。
- 类的内部实现状态继续使用 `self._name`，不要求为每个内部字段提供公开属性。

## 配置来源

- 用户配置保存在 JSON 中，并通过配置模型校验。
- 环境变量只用于浏览器渠道、日志级别、运行目录等部署或诊断覆盖。
- 小说路径、章节范围、发布选项和登录状态不放入环境变量。

## 运行安全约束

- 发布、同步、登录、授权导入和授权重置共享 `fanqie_browser` 资源，同一时间只允许一个任务操作番茄平台。
- 配置、账号索引、登录状态和小说正文使用同目录临时文件写入，刷盘成功后再原子替换目标文件。
- 配置、账号索引和登录状态覆盖前保留最近一份 `.bak` 备份；正文同步继续保留按章节编号的历史备份。
- 浏览器定位允许按预定方案回退；主流程最终失败时必须记录操作阶段、页面 URL、定位器、异常类型和失败截图。

## 番茄页面模块

- `dialogs/publishing.py` 是发布弹窗公开门面；内容检测、AI 选项、发布确认和定时发布分别位于独立模块。
- 定时发布继续按流程编排、开关、日期和时间拆分，日期与时间定位细节不泄漏给提交状态流。
- `pages/editor.py` 是编辑器公开门面；章节导航、字段识别、内容写入和草稿保存分别位于独立模块。
- 生产代码继续通过公开门面导入；兼容门面不承载页面实现，页面及弹窗模块原则上保持在 450 行以内。

## 前端模块

- `assets/styles.css` 只作为样式入口，按 shell、workspace、terminal、legacy-tools 和 controls 顺序加载源模块。
- `core/task_panel.js` 负责通用任务状态与日志面板，`core/fanqie_task_actions.js` 负责番茄页面绑定和载荷收集。
- `assets/bundle.js` 是提交到仓库的生成产物，测试必须验证它与 `tools/bundle_js.py` 声明的源文件完全一致。
